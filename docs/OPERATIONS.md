# 운영 안내

## 직원 계정

공개 회원가입은 없습니다. 관리자가 Supabase 대시보드에서 계정을 만들고 직원 명단에 등록합니다.
**로그인만 된 계정은 아무것도 바꿀 수 없고**, `staff_members`에 활성 상태로 등록돼야 주문을 보고 수정할 수 있습니다.

### 발급

1. Authentication → Users → **Add user → Create new user**
   이메일·임시 비밀번호 입력, **Auto Confirm User** 체크. (실제 개인 메일 대신 부스 공용 주소 사용 가능)
2. SQL Editor에서 권한 등록:

```sql
insert into public.staff_members (user_id, display_name)
select id, '홍길동' from auth.users where email = 'staff1@example.com'
on conflict (user_id) do update set active = true, display_name = excluded.display_name;
```

3. 직원에게 이메일·비밀번호를 직접 전달(메신저 공개 채팅방 금지). 비밀번호는 기기별로 다르게 두는 것을 권장합니다.

### 비활성화 (분실·퇴출·축제 종료)

```sql
update public.staff_members set active = false
where user_id = (select id from auth.users where email = 'staff1@example.com');
```

다음 요청부터 바로 차단됩니다(RPC·조회 모두 매번 확인). 이미 열린 세션까지 끊으려면 Authentication → Users에서 해당 사용자를 **Ban** 하거나 삭제하세요.
축제가 끝나면 모든 직원 계정을 비활성화합니다.

### 등록 현황 확인

```sql
select u.email, s.display_name, s.active, s.created_at
from public.staff_members s join auth.users u on u.id = s.user_id order by s.created_at;
```

## 운영 전 점검표

배포·환경

- [ ] `.env.local` 값으로 빌드 후 `npx wrangler deploy` 로 **재배포**, `/`가 ‘운영 연결 준비 중’이 아니라 번호 입력 화면을 보여준다
- [ ] Supabase Auth: 공개 회원가입 꺼짐, Site URL = 배포 URL
- [ ] Publications `supabase_realtime`에 `public_service_state`, `public_order_status`, `orders` 포함
- [ ] service_role/secret 키가 빌드 결과물·저장소·코드 어디에도 없다
- [ ] 메뉴 4종·가격이 메뉴판과 같다 (`select * from menus order by sort_order;`)

권한 (시크릿 창에서)

- [ ] 로그인하지 않은 상태로 `/admin` → 로그인 화면으로 이동
- [ ] 직원 명단에 없는 계정으로 로그인 → ‘직원 권한이 없는 계정이에요’
- [ ] 손님 화면에 메뉴 내역·메모·직원 정보가 보이지 않는다

현장 리허설 (직원 휴대폰 2대 + 손님 휴대폰 iPhone/Android 각 1대)

- [ ] 직원 A: 회차 시작 → 23번 등록. 손님: 23 입력 → ‘맛있게 준비 중이에요’
- [ ] 직원 B 화면에도 23번이 나타난다
- [ ] 24번을 먼저 조리 완료 → 손님 23번은 계속 준비 중, ‘지금 받아가세요’에 24번만
- [ ] 23번 조리 완료 → 손님 화면이 새로고침 없이 초록 ‘조리 완료!’ (2초 이내인지 체감 확인)
- [ ] 등록하면 손님 화면 ‘준비 중…’에 번호가 보이고, 조리 완료 시 ‘지금 받아가세요’로, 수령 완료 시 목록에서 빠진다
- [ ] 직원 A·B가 같은 주문을 동시에 탭 → 하나만 반영, 다른 쪽은 ‘다른 기기에서 먼저 바뀌었어요’
- [ ] 손님 폰 비행기 모드 → ‘연결을 확인하고 있어요 · 마지막 확인’ 표시 → 해제 후 최신 상태로 복구
- [ ] 손님 폰 잠금/다른 앱 → 복귀 시 최신 상태
- [ ] 회차 종료가 미처리 주문 때문에 막히는지, 정리 후 종료되는지
- [ ] 공통 QR을 실제 인쇄 크기로 출력해 1~2m 거리에서 스캔

## 직원용 짧은 사용 안내

> 부스에 출력해 붙여 두세요.

1. **로그인** — `/admin`. 상단에 회차 이름과 ‘운영 중’, ‘실시간 연결됨’이 보이면 준비 완료.
2. **회차 시작** (하루 한 번) — 열린 회차가 없으면 날짜·이름 확인 후 ‘회차 시작’.
3. **주문 받으면 바로 등록** — 번호 칸에 **다음 번호가 자동으로 채워져 있어요**(새 회차는 1번부터). 그 번호를 손님에게 말로 알려주고 ‘등록’. 다른 번호를 써야 하면 칸을 눌러 바꿔 입력. 메뉴·메모는 선택.
   - ‘이미 등록된 번호예요’가 뜨면 번호를 다시 확인. 취소·수령 완료된 번호도 같은 날 재사용하지 않습니다.
   - 번호를 잘못 넣었다면: 그 주문을 **취소**하고 올바른 번호로 새로 등록.
4. **음식이 전부 준비되면** — ‘준비 중’ 탭에서 그 번호의 **조리 완료**. 일부 메뉴만 나왔을 땐 누르지 않습니다.
5. **손님에게 전달하면** — ‘수령 대기’ 탭에서 **수령 완료**.
6. **주문 취소** (손님이 취소하거나 번호를 잘못 넣었을 때) — 카드의 빨간 **취소** → 사유(선택) 입력 → ‘주문 취소’. 손님 화면에는 ‘취소된 주문이에요’로 표시됩니다.
7. **잘못 눌렀을 때** — 아래 검은 알림의 **되돌리기**(8초). 지났으면 번호를 눌러 상세에서 되돌리기.
8. **빨간 ‘저장하지 못했어요’** — 저장되지 않은 것입니다. 연결 확인 후 ‘다시 시도’.
9. **영업 종료** — 남은 주문을 모두 수령 완료/취소한 뒤 상단 ‘회차 종료’.

손님 안내 멘트: “주문번호는 ○번이에요. QR로 들어가서 번호 넣으시면 다 되면 화면이 초록색으로 바뀌어요. 화면을 끄면 알림은 안 가니 가끔 확인해주세요.”
